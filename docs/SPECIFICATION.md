## システム概要

### プロジェクト名
**fitReserve** - 制服採寸予約管理システム

### 目的
制服販売会社において、顧客の採寸予約を効率的に管理し、店舗スタッフの業務を効率化するためのWebアプリケーション。

### 対象ユーザー
- **エンドユーザー（顧客）**: 保護者・学生（予約フォームのみ）
- **店舗スタッフ**: 予約確認、採寸実施、顧客対応
- **管理者**: 店舗管理、プロジェクト管理、統計分析

### ビジネス背景
- 制服の新入生向け採寸予約が年に数回（入学シーズン、夏服切替など）
- 複数の学校と取引があり、学校ごとに異なる制服がある
- 複数店舗で予約を受け付け、各店舗の受付可能枠を管理する必要がある
- 電話予約からWeb予約へ移行し、業務効率化を図る

## ビジネス要件

### BR-1: 予約受付の効率化
- Web上で24時間予約受付可能
- 店舗ごとの受付可能枠をリアルタイムで表示
- 予約の重複を自動的に防止
- 予約確定時に自動でメール通知（将来実装）

### BR-2: 複数店舗・複数学校対応
- 複数店舗の予約を一元管理
- 学校ごとに異なる制服情報を管理
- プロジェクト（キャンペーン期間）ごとに対象店舗・対象学校を設定可能

### BR-3: 柔軟な予約枠設定
- プロジェクトごとに予約時間間隔を設定（20分/30分/60分）
- 店舗ごとに営業時間・定休日を設定
- 臨時休業・特別営業時間の設定が可能

### BR-4: 顧客情報管理
- 顧客の基本情報（氏名、連絡先、学校、学年）
- 顧客のヒアリング情報（身長、体重、足のサイズ）
- 過去の予約履歴

### BR-5: 予約ステータス管理
- **pending**: 予約受付（未確認）
- **confirmed**: 予約確定
- **completed**: 採寸完了
- **cancelled**: キャンセル

### BR-6: データの論理削除
- すべてのデータは物理削除せず、`deleted_at` で論理削除
- 削除データも履歴として保持

## ユーザーロール

### 管理者（admin）
- **権限**: すべての機能にアクセス可能
- **主な業務**:
  - 店舗マスタの登録・編集・削除
  - 学校マスタの登録・編集・削除
  - プロジェクトの作成・管理
  - スタッフアカウントの管理
  - 全店舗の予約状況確認
  - 統計レポート閲覧

### スタッフ（staff）
- **権限**: 所属店舗のデータのみ閲覧・編集可能
- **主な業務**:
  - 所属店舗の予約確認
  - 予約ステータスの更新（確定・完了・キャンセル）
  - 顧客情報の閲覧・編集
  - スケジュール枠の調整

### 閲覧専用（readonly）
- **権限**: データの閲覧のみ
- **主な業務**:
  - 予約状況の確認
  - 顧客情報の閲覧
  - レポートの閲覧

### 一般ユーザー（顧客）
- **権限**: 予約フォームからの予約登録のみ（ログイン不要）
- **主な業務**:
  - 予約の新規登録
  - 予約内容の確認（予約番号で検索）

## 主要機能

### F-1: 予約管理機能

#### F-1-1: 予約新規登録（顧客向け）
- **画面**: 公開予約フォーム
- **入力項目**:
  - プロジェクト選択
  - 店舗選択
  - 学校選択
  - 予約日時選択（空き枠から選択）
  - 顧客情報入力
    - 氏名（必須）
    - 氏名カナ
    - 性別（必須）
    - 学年
    - 電話番号（必須）
    - メールアドレス
    - 保護者氏名
  - 採寸情報入力
    - 身長
    - 体重
    - 足のサイズ
  - 備考
- **処理**:
  - 予約番号を自動生成（例: RES-2026-08-001）
  - 予約確定メール送信（将来実装）
  - スケジュールの予約済数をインクリメント

#### F-1-2: 予約一覧表示（スタッフ向け）
- **表示項目**:
  - 予約番号
  - 予約日時
  - 店舗名
  - 顧客氏名
  - 学校名
  - ステータス
- **フィルター機能**:
  - 日付範囲
  - 店舗
  - ステータス
  - 学校
- **ソート機能**: 予約日時、作成日時

#### F-1-3: 予約詳細表示・編集
- **表示項目**: すべての予約情報
- **編集可能項目**:
  - 予約日時（空き枠のみ）
  - 顧客情報
  - 採寸情報
  - ステータス
  - 備考

#### F-1-4: 予約キャンセル
- **処理**:
  - ステータスを `cancelled` に更新
  - スケジュールの予約済数をデクリメント
  - キャンセル通知メール送信（将来実装）

## ビジネスルール

### BL-1: 予約番号の生成規則
- 形式: `RES-{YYYY}-{MM}-{連番3桁}`
- 例: `RES-2026-08-001`, `RES-2026-08-002`
- 連番は月ごとにリセット

### BL-2: 予約可能期間
- プロジェクトの開始日〜終了日の範囲内のみ予約可能
- 過去の日時は予約不可

### BL-3: 予約枠の計算
- 営業時間と予約時間間隔から自動計算
- 例: 9:00-17:00、30分間隔 → 16枠（9:00, 9:30, ..., 16:30）

### BL-4: 予約の重複チェック
- 同一店舗・同一日時・同一時刻で受付可能数を超える予約は不可
- 予約時に `schedules.reserved_count` をチェック

### BL-5: プロジェクトの店舗・学校制限
- `project_stores` にレコードがない場合 → 全店舗が対象
- `project_stores` にレコードがある場合 → 指定店舗のみ対象
- `project_schools` にレコードがない場合 → 全学校が対象
- `project_schools` にレコードがある場合 → 指定学校のみ対象

### BL-6: 論理削除の扱い
- `deleted_at IS NULL` のデータのみ表示（アクティブなデータ）
- 削除操作は `deleted_at` に現在日時を設定
- 物理削除は管理者が手動で実施（通常は不要）

### BL-7: スタッフの所属店舗制限
- staff権限のユーザーは `store_id` で指定された店舗のデータのみアクセス可能
- admin権限のユーザーは全店舗のデータにアクセス可能

### BL-8: ステータス遷移
```
pending → confirmed → completed
   ↓           ↓
cancelled   cancelled
```
- `pending` から直接 `completed` への変更は不可
- `completed` から他のステータスへの変更は不可

## 運用要件

### OP-1: バックアップ
- 日次: 深夜2:00に自動バックアップ
- 保持期間: 30日間
- バックアップ先: 外部ストレージ

### OP-2: データ保持期間
- 予約データ: 無期限（論理削除のみ）
- ログデータ: 1年間

### OP-3: メンテナンス時間
- 毎週日曜日 2:00-4:00（システムメンテナンス可能時間）
- 緊急メンテナンスは随時実施

### OP-4: 監視項目
- サーバーの稼働状況
- データベース接続状況
- ディスク使用率
- レスポンスタイム

### OP-5: セキュリティ
- パスワードはbcryptでハッシュ化
- JWT トークンは24時間で失効
- HTTPS 通信必須（本番環境）
- CORS 設定による不正アクセス防止
